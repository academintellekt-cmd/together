# Решение проблемы с VPN и локальной сетью

## Проблема

VPN блокирует доступ к локальной сети (ESP32), перенаправляя весь трафик через VPN-сервер.

## Решения

### Решение 1: Split Tunneling (Рекомендуется)

Настройте VPN так, чтобы он **не перенаправлял трафик локальной сети**:

#### Для большинства VPN клиентов:
1. Откройте настройки VPN
2. Найдите раздел "Split Tunneling" или "Исключения"
3. Добавьте исключение для подсети `192.168.0.0/16` или `192.168.0.0/24`
4. Или добавьте конкретный IP: `192.168.0.172`

#### Для популярных VPN:

**NordVPN:**
- Settings → Advanced → Split Tunneling
- Добавьте `192.168.0.172` в исключения

**ExpressVPN:**
- Settings → Network Lock → Split Tunneling
- Добавьте локальную подсеть

**ProtonVPN:**
- Settings → Connection → Split Tunneling
- Исключите локальную сеть

**OpenVPN:**
- В конфигурационном файле добавьте:
```
route 192.168.0.0 255.255.255.0 net_gateway
```

### Решение 2: Статический маршрут (Windows)

Добавьте статический маршрут для локальной сети, чтобы он не шел через VPN:

```powershell
# Запустите PowerShell от имени администратора
route add 192.168.0.0 mask 255.255.255.0 192.168.0.1 metric 1 -p
```

Где `192.168.0.1` - IP адрес вашего роутера.

### Решение 3: Отключение VPN для локальной сети

Временно отключайте VPN при работе с ESP32, или используйте функцию "Pause VPN" если доступна.

### Решение 4: Использование другого сетевого интерфейса

Если VPN создает виртуальный сетевой адаптер, можно настроить привязку к конкретному интерфейсу.

## Проверка работы

После настройки проверьте:

```powershell
# Проверка доступности ESP32
ping 192.168.0.172

# Проверка HTTP доступа
Invoke-WebRequest -Uri "http://192.168.0.172/api/dmx/status" -TimeoutSec 3
```

## Автоматическое определение проблемы

Сервер теперь автоматически определяет проблемы с VPN и выводит предупреждения в логи.
