# Архитектура проекта для масштабирования до 30+ игр

## Текущие проблемы
1. ❌ Отдельный HTML файл для каждого квиза (gnu-quiz.html) - не масштабируется
2. ❌ Все квизы в одном объекте в server.js - сложно поддерживать
3. ❌ Вопросы в одном файле questions.txt - нет разделения по квизам
4. ❌ Дублирование кода в HTML файлах
5. ❌ Жестко закодированные ID квизов в коде

## Предлагаемая структура

```

├── public/

│   │   ├── solo.html           # Универсальная страница одиночной игры
│   │   └── host.html           # Универсальная страница мультиплеера
│   ├── player.html             # Страница игрока
│   ├── leaderboard.html        # Рейтинг
│   └── styles/
│       ├── brand-style.css
│       └── common.css
│
├── data/
│   ├── quizzes/                # Конфигурации квизов
│   │   ├── gnu.json           # Конфигурация квиза ГНУ
│   │   ├── event-2024-01.json # Пример: квиз для мероприятия 2024-01
│   │   └── template.json      # Шаблон для создания новых квизов
│   │

│   ├── index.js                # Главный файл сервера
│   ├── routes/
│   │   ├── quizzes.js         # Маршруты для квизов

│   │   └── leaderboard.js     # Маршруты для рейтинга

│   │   ├── quiz-loader.js     # Загрузка квизов из файлов

```

## Конвенции именования

### Квизы
- **ID квиза**: `{event-slug}-{type}`
  - Примеры: `gnu`, `corporate-2024-01`, `birthday-anna-2024`
  - Формат: `{название-мероприятия}-{дата-или-идентификатор}`

### Файлы конфигурации
- **JSON конфигурация**: `data/quizzes/{quiz-id}.json`
- **Вопросы**: `data/questions/{quiz-id}.txt`

### URL маршруты
- Главная: `/`
- Выбор режима: `/game/{quiz-id}/mode`
- Одиночная игра: `/game/{quiz-id}/solo`
- Мультиплеер: `/game/{quiz-id}/host`
- Игрок: `/game/{quiz-id}/player?room={code}`

## Преимущества новой структуры

1. ✅ **Масштабируемость**: Легко добавлять новые квизы (просто создать JSON + TXT)
2. ✅ **Модульность**: Код разделен на логические модули
3. ✅ **Единый шаблон**: Один HTML файл для всех квизов
4. ✅ **Управляемость**: Все конфигурации в одном месте
5. ✅ **Гибкость**: Легко менять настройки без изменения кода
6. ✅ **Тестируемость**: Каждый модуль можно тестировать отдельно

## План миграции

1. Создать структуру папок
2. Создать шаблон конфигурации квиза
3. Мигрировать текущий квиз ГНУ в новую структуру
4. Создать универсальную страницу mode-select.html
5. Обновить server.js для загрузки квизов из файлов
6. Обновить index.html для динамической загрузки
7. Протестировать с текущим квизом
8. Документировать процесс добавления новых квизов
