# Архитектура проекта квиз-платформы "ВМЕСТЕ"

## ✅ Текущая реализация

Проект использует масштабируемую архитектуру с разделением данных и кода.

## 🏗️ Архитектурные решения

### 1. Модульная структура данных

**Квизы загружаются из файлов:**
- Конфигурация: `data/quizzes/{quiz-id}.json`
- Вопросы: `data/questions/{questions-file}.txt`

**Преимущества:**
- ✅ Легко добавлять новые квизы (просто создать JSON + TXT)
- ✅ Не нужно изменять код для добавления квиза
- ✅ Разделение данных и логики

### 2. Серверная архитектура

**Основные компоненты:**
- `server.js` - главный файл с Express сервером и Socket.io
- `server/utils/quiz-loader.js` - загрузка и парсинг квизов

**Функциональность:**
- REST API для получения списка квизов
- WebSocket для реального времени (мультиплеер)
- Управление комнатами и игроками
- Интеграция с Google Sheets для рейтинга

### 3. Клиентская архитектура

**Страницы:**
- `index.html` - главная страница с динамической загрузкой квизов
- `mode-select.html` - выбор режима (соло/мультиплеер) с проверкой пароля
- `solo.html` - одиночная игра с рейтингом
- `host.html` - главный экран для хоста в мультиплеере
- `player.html` - интерфейс игрока в мультиплеере
- `gnu-quiz.html` - специальная страница для квиза ГНУ

**Особенности:**
- Адаптивный дизайн (мобильные и десктоп)
- Брендинг с персонажами
- Автоматический переход к следующему вопросу в мультиплеере

## 📋 Конвенции именования

### Квизы
- **ID квиза**: `{event-slug}` или `{event-slug}-{type}`
  - Примеры: `gnu`, `corporate-2024-01`, `birthday-anna-2024`
  - Формат: `{название-мероприятия}-{дата-или-идентификатор}`

### Файлы конфигурации
- **JSON конфигурация**: `data/quizzes/{quiz-id}.json`
- **Вопросы**: `data/questions/{questions-file}.txt` (указывается в JSON)

### URL маршруты
- Главная: `/`
- Выбор режима: `/mode-select.html?quiz={quiz-id}`
- Одиночная игра: `/solo.html?quiz={quiz-id}`
- Мультиплеер (хост): `/host.html?quiz={quiz-id}`
- Игрок: `/player.html?room={code}`

## 🔄 Потоки данных

### Мультиплеер
1. Хост создает комнату → сервер генерирует код
2. Игроки подключаются → Socket.io соединение
3. Хост запускает игру → сервер отправляет вопросы
4. Игроки отвечают → сервер обрабатывает ответы
5. Все готовы → автоматический переход к следующему вопросу
6. Игра завершена → финальные результаты

### Одиночная игра
1. Пользователь выбирает квиз → загрузка вопросов
2. Игра начинается → вопросы показываются последовательно
3. Пользователь отвечает → подсчет очков
4. Игра завершена → сохранение в рейтинг (Google Sheets)

## 🎯 Преимущества текущей архитектуры

1. ✅ **Масштабируемость**: Легко добавлять новые квизы (просто создать JSON + TXT)
2. ✅ **Модульность**: Код разделен на логические модули
3. ✅ **Гибкость**: Легко менять настройки без изменения кода
4. ✅ **Оптимизация**: Удалены неиспользуемые файлы
5. ✅ **Автоматизация**: Автоматический переход к следующему вопросу
6. ✅ **Производительность**: Задержка после ответа 0.75 секунды
