# Архитектура локального режима

## ✅ ПРАВИЛЬНАЯ АРХИТЕКТУРА

### Центральный сервер (хост-компьютер)

**IP адрес:** например, `192.168.1.10` или `192.168.1.20`

**Что запускается:**
- ✅ `server.js` с локальным режимом
- ✅ Все HTML страницы (station.html, local-host.html, и т.д.)
- ✅ Socket.io сервер для управления станциями
- ✅ API для регистрации и управления станциями

**Команда запуска:**
```bash
cd /path/to/together
node server.js
# или
npm start
```

**Проверка:**
- Сервер должен быть доступен по `http://<IP_СЕРВЕРА>:3000`
- В консоли должно быть: `✅ Локальные модули доступны`

### Станции (компьютеры игроков)

**IP адреса:** `192.168.1.21` - `192.168.1.29` (станции 1-9)

**Что НЕ нужно запускать:**
- ❌ `server.js` - НЕ запускайте сервер на станциях!
- ❌ Node.js сервер - НЕ нужен на станциях!

**Что нужно сделать:**
1. ✅ Открыть браузер на станции
2. ✅ Открыть страницу с центрального сервера:
   - `http://<IP_СЕРВЕРА>:3000/station.html`
   - Например: `http://192.168.1.10:3000/station.html`
3. ✅ Страница автоматически подключится к центральному серверу

**Пример:**
- Центральный сервер: `192.168.1.10:3000`
- Станция 1 (192.168.1.21): открыть `http://192.168.1.10:3000/station.html`
- Станция 2 (192.168.1.22): открыть `http://192.168.1.10:3000/station.html`
- И так далее...

## ❌ ЧАСТЫЕ ОШИБКИ

### Ошибка 1: Запуск server.js на станциях
**Неправильно:**
```bash
# На станции 192.168.1.21
cd C:\together
node server.js  # ❌ НЕ ДЕЛАЙТЕ ЭТОГО!
```

**Правильно:**
- Просто откройте браузер и перейдите на `http://192.168.1.10:3000/station.html`

### Ошибка 2: Открытие station.html по локальному IP станции
**Неправильно:**
```bash
# На станции 192.168.1.21
http://192.168.1.21:3000/station.html  # ❌ Это не сработает, если сервер не запущен на станции
```

**Правильно:**
```bash
# На станции 192.168.1.21
http://192.168.1.10:3000/station.html  # ✅ Открыть страницу с центрального сервера
```

### Ошибка 3: Деплой server.js на станции
**Неправильно:**
- Деплоить `server.js` на каждую станцию
- Запускать Node.js на каждой станции

**Правильно:**
- Деплоить только на центральный сервер
- На станциях только браузер с открытой страницей

## 📋 Чеклист настройки

### На центральном сервере:
- [ ] Установлен Node.js
- [ ] Установлены зависимости (`npm install`)
- [ ] Запущен `server.js`
- [ ] Сервер доступен по IP адресу (не только localhost)
- [ ] В консоли: `✅ Локальные модули доступны`

### На станциях:
- [ ] Установлен браузер (Chrome, Firefox, Edge)
- [ ] Станция в той же сети, что и сервер
- [ ] Открыта страница `http://<IP_СЕРВЕРА>:3000/station.html`
- [ ] Страница показывает "Станция X подключена"
- [ ] НЕ запущен `server.js` на станции

## 🔍 Проверка правильности настройки

### Проверка 1: Центральный сервер
```bash
# На центральном сервере
curl http://localhost:3000/api/local/stations/status
# Должен вернуть JSON с информацией о станциях
```

### Проверка 2: Станция
```bash
# На станции (или с другого компьютера)
curl http://<IP_СЕРВЕРА>:3000/station.html
# Должна вернуться HTML страница
```

### Проверка 3: Связь станции с сервером
1. Откройте `http://<IP_СЕРВЕРА>:3000/local-host.html` на центральном сервере
2. Должны отобразиться подключенные станции (зеленым цветом)
3. Если станция не отображается - проверьте, что страница открыта на станции

## 💡 Почему так?

**Преимущества централизованной архитектуры:**
1. ✅ Простота управления - один сервер вместо 9
2. ✅ Легче обновлять - обновляете только центральный сервер
3. ✅ Меньше ресурсов - станции не тратят ресурсы на Node.js
4. ✅ Надежность - если сервер упал, просто перезапустите его
5. ✅ Единая точка управления - все команды идут через один сервер

   - Откройте `http://<IP_СЕРВЕРА>:3000/local-host.html` на центральном сервере
