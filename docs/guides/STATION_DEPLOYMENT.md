# Развертывание файлов на станции

Система автоматического развертывания позволяет загружать файлы проекта на все станции через локальный сервер без использования флешки.

📖 **Для Windows:** см. [WINDOWS_DEPLOYMENT.md](./WINDOWS_DEPLOYMENT.md)

## Возможности

- ✅ Автоматическое развертывание на все станции (192.168.1.21-29)
- ✅ Поддержка SSH ключей и паролей
- ✅ Создание резервных копий перед обновлением
- ✅ Автоматический перезапуск приложения на станциях
- ✅ Веб-интерфейс для управления развертыванием
- ✅ API для программного управления

## Использование через веб-интерфейс

1. Откройте страницу развертывания: `http://localhost:3000/station-deploy.html`
2. Заполните параметры:
   - **Имя пользователя SSH**: обычно `pi` для Raspberry Pi
   - **Пароль SSH**: опционально, если используется SSH ключ
   - **Путь к проекту**: путь на станции (по умолчанию `/home/pi/together`)
3. Нажмите "Развернуть на все станции"
4. Процесс развертывания запустится в фоновом режиме
5. Проверьте логи сервера для отслеживания прогресса

## Использование через командную строку

### Базовое использование (SSH ключи)

```bash
./scripts/deploy-local.sh
```

### С указанием пользователя

```bash
./scripts/deploy-local.sh pi
```

### С паролем

```bash
./scripts/deploy-local.sh pi raspberry
```

### С пользовательским путем

```bash
./scripts/deploy-local.sh pi raspberry /home/pi/my-project
```

## Использование через API

### Запуск развертывания

```bash
curl -X POST http://localhost:3000/api/local/stations/deploy \
  -H "Content-Type: application/json" \
  -d '{
    "username": "pi",
    "password": "",
    "stationPath": "/home/pi/together"
  }'
```

### Проверка статуса станций

```bash
curl http://localhost:3000/api/local/stations/deploy/status
```

## Что происходит при развертывании

1. **Создание архива**: Создается архив `quiz-station-deploy.tar.gz` с файлами проекта
2. **Проверка доступности**: Проверяется доступность каждой станции через ping
3. **Загрузка файлов**: Архив и скрипт развертывания загружаются на каждую станцию через SCP
4. **Резервная копия**: Создается резервная копия текущих файлов на станции
5. **Очистка**: Удаляются старые файлы проекта
6. **Распаковка**: Распаковывается новый архив
7. **Установка зависимостей**: Выполняется `npm install --production`
8. **Запуск**: Перезапускается приложение через PM2

## Требования

### На сервере (локальный компьютер)

- Node.js и npm
- Bash
- SSH клиент
- `sshpass` (опционально, для использования паролей): `brew install hudochenkov/sshpass/sshpass`
- SSH ключи настроены (рекомендуется) или известен пароль для станций

### На станциях

- SSH сервер запущен и доступен
- Порт 22 открыт в файрволе
- Node.js и npm установлены
- PM2 для управления процессами
- Доступ к сети (192.168.1.x)

📖 **Подробная инструкция по настройке SSH:** см. [SSH_SETUP_STATIONS.md](./SSH_SETUP_STATIONS.md)

## Исключаемые файлы при развертывании

Следующие файлы и папки не включаются в архив развертывания:

- `node_modules/`
- `.git/`
- `*.backup`
- `*.log`
- `*.tar.gz`
- Документация (README.md, CHECKLIST.md и т.д.)
- `public/fonts/`
- `.env.local`
- `server/local/`
- `public/local-*.html`

## Устранение неполадок

### Станция недоступна

Если станция не отвечает на ping, она будет пропущена. Проверьте:
- Сетевое подключение
- IP адрес станции
- Настройки файрвола

### Ошибка SSH подключения

- Убедитесь, что SSH сервер запущен на станции
- Проверьте правильность имени пользователя и пароля
- Если используете SSH ключи, убедитесь, что они настроены правильно

### Ошибка при установке зависимостей

- Проверьте, что Node.js и npm установлены на станции
- Убедитесь, что на станции достаточно места на диске
- Проверьте логи развертывания на сервере

### PM2 не запускает приложение

- Убедитесь, что PM2 установлен: `npm install -g pm2`
- Проверьте логи PM2: `pm2 logs quiz-site`
- Убедитесь, что файл `server.js` существует и корректен

## Безопасность

⚠️ **Важно**: Пароли передаются через командную строку. Для продакшн-среды рекомендуется:

1. Использовать SSH ключи вместо паролей
2. Настроить SSH ключи без парольной фразы для автоматизации
3. Ограничить доступ к API развертывания (например, только с localhost)

## Примеры использования

### Развертывание после изменений в коде

```bash
# Внесли изменения в код
git add .
git commit -m "Обновление функционала"

# Развертывание на все станции
./scripts/deploy-local.sh pi
```

### Развертывание через веб-интерфейс

1. Откройте `http://localhost:3000/station-deploy.html`
2. Заполните форму
3. Нажмите "Развернуть"
4. Отслеживайте прогресс в логах сервера

### Автоматическое развертывание при коммите

Можно настроить git hook для автоматического развертывания:

```bash
# .git/hooks/post-commit
#!/bin/bash
./scripts/deploy-local.sh pi
```
