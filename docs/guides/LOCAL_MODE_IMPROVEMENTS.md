# Улучшения локального режима управления станциями

## Что было реализовано

### 1. Очередь команд для станций

**Проблема:** Если Socket.io соединение терялось, команды терялись и не доставлялись на станцию.

**Решение:** Добавлена очередь команд для каждой станции. Все команды сначала добавляются в очередь, а затем пытаются быть отправлены через Socket.io. Если Socket.io недоступен, команды остаются в очереди и могут быть получены через HTTP polling.

**Реализация:**
- `LocalModeManager.enqueueCommand()` - добавление команды в очередь
- `LocalModeManager.dequeueCommands()` - получение всех команд из очереди (для HTTP polling)
- `LocalModeManager.dequeueCommand()` - получение одной команды (для Socket.io)

### 2. HTTP Polling как fallback

**Проблема:** Если Socket.io недоступен, станция не могла получать команды.

**Решение:** Станция периодически (каждые 2 секунды) опрашивает сервер через HTTP endpoint `/api/local/stations/:number/commands` для получения команд из очереди.

**Преимущества:**
- Работает даже если Socket.io недоступен
- Гарантирует доставку команд
- Автоматически активируется при потере Socket.io соединения
- Увеличивает частоту опроса при потере соединения (до 1 секунды)

### 3. Улучшенное переподключение Socket.io

**Проблема:** При переподключении станции терялись команды, отправленные пока она была отключена.

**Решение:** 
- При переподключении станции все накопленные команды из очереди автоматически отправляются через Socket.io
- Станция получает текущее состояние вместе с подтверждением подключения
- Автоматическое переподключение с экспоненциальной задержкой

**Настройки Socket.io:**
```javascript
{
    reconnection: true,
    reconnectionDelay: 1000,
    reconnectionDelayMax: 5000,
    reconnectionAttempts: Infinity,
    timeout: 20000
}
```

### 4. Автоматическое восстановление соединения

**Реализация на станции:**
- Socket.io автоматически переподключается при потере соединения
- HTTP polling активируется как fallback
- При восстановлении Socket.io соединения возвращается нормальная частота polling
- Все команды из очереди автоматически доставляются при переподключении

## Как это работает

### Сценарий 1: Нормальная работа (Socket.io подключен)

1. Сервер отправляет команду → добавляет в очередь → отправляет через Socket.io
2. Станция получает команду через Socket.io
3. HTTP polling работает в фоне (низкая частота), но не используется активно

### Сценарий 2: Потеря Socket.io соединения

1. Сервер отправляет команду → добавляет в очередь → Socket.io недоступен
2. Команда остается в очереди
3. Станция обнаруживает потерю соединения
4. HTTP polling увеличивает частоту до 1 секунды
5. Станция получает команду через HTTP polling
6. Socket.io пытается переподключиться в фоне

### Сценарий 3: Переподключение после потери соединения

1. Socket.io успешно переподключается
2. Сервер отправляет все накопленные команды из очереди через Socket.io
3. HTTP polling возвращается к нормальной частоте (2 секунды)
4. Станция синхронизирует состояние с сервером

## API

### HTTP Endpoints

#### GET /api/local/stations/:stationNumber/commands
Получение команд из очереди для станции (HTTP polling)

**Ответ:**
```json
{
  "success": true,
  "stationNumber": 1,
  "commands": [
    {
      "id": 1234567890,
      "command": "navigate",
      "params": { "page": "quiz", "roomCode": "ABC123" },
      "timestamp": 1234567890
    }
  ],
  "state": {
    "currentPage": "waiting",
    "pageData": {},
    "customState": {}
  },
  "timestamp": 1234567890
}
```

### Методы LocalModeManager

#### enqueueCommand(stationNumber, command, params)
Добавляет команду в очередь для станции.

#### dequeueCommands(stationNumber)
Получает все команды из очереди и очищает её (для HTTP polling).

#### dequeueCommand(stationNumber)
Получает одну команду из очереди (для Socket.io).

#### getQueueSize(stationNumber)
Возвращает количество команд в очереди.

#### clearQueue(stationNumber)
Очищает очередь команд для станции.

## Преимущества новой архитектуры

1. **Надежность:** Команды не теряются даже при потере соединения
2. **Автоматизация:** Станция подключается один раз, дальше все работает автоматически
3. **Отказоустойчивость:** Два канала доставки (Socket.io + HTTP polling)
4. **Гибкость:** Можно управлять станцией в любой момент, независимо от состояния соединения
5. **Простота:** Не требует дополнительной инфраструктуры (браузер работает как есть)

## Использование

### Для пользователя (ведущего):

1. Запустите сервер
2. На станции откройте `/local-station.html` один раз
3. Станция автоматически зарегистрируется и начнет получать команды
4. Используйте окно управления для отправки команд
5. Команды будут доставлены даже если соединение временно прервалось

### Для разработчика:

Все команды теперь автоматически добавляются в очередь перед отправкой через Socket.io. Это гарантирует их доставку через любой доступный канал (Socket.io или HTTP polling).

## Технические детали

- Очередь команд хранится в памяти сервера
- При перезапуске сервера очереди очищаются (команды теряются)
- В будущем можно добавить персистентное хранение очереди (Redis, база данных)
- HTTP polling работает только когда Socket.io недоступен (оптимизация нагрузки)
- При нормальной работе используется Socket.io (меньше нагрузка на сервер)
