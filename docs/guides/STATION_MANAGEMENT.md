## Архитектура

### ✅ Правильная архитектура

**Центральный сервер (хост-компьютер)**

**IP адрес:** например, `192.168.1.10` или `192.168.1.20`

**Что запускается:**
- ✅ `server.js` с локальным режимом
- ✅ Все HTML страницы (station.html, local-host.html, и т.д.)
- ✅ Socket.io сервер для управления станциями
- ✅ API для регистрации и управления станциями
- ✅ Очередь команд для надежной доставки

**Команда запуска:**
```bash
cd /path/to/together
node server.js
# или
npm start
```

**Проверка:**
- Сервер должен быть доступен по `http://<IP_СЕРВЕРА>:3000`
- В консоли должно быть: `✅ Локальные модули доступны`

### Станции (компьютеры игроков)

**IP адреса:** `192.168.1.21` - `192.168.1.29` (станции 1-9)

**Что НЕ нужно запускать:**
- ❌ `server.js` - НЕ запускайте сервер на станциях!
- ❌ Node.js сервер - НЕ нужен на станциях!
- ❌ Локальные файлы проекта - НЕ нужны!

**Что нужно сделать:**
1. ✅ Открыть браузер на станции
2. ✅ Открыть страницу с центрального сервера:
   - `http://<IP_СЕРВЕРА>:3000/station.html`
   - Например: `http://192.168.1.10:3000/station.html`
3. ✅ Страница автоматически подключится к центральному серверу

**Пример:**
- Центральный сервер: `192.168.1.10:3000`
- Станция 1 (192.168.1.21): открыть `http://192.168.1.10:3000/station.html`
- Станция 2 (192.168.1.22): открыть `http://192.168.1.10:3000/station.html`
- И так далее...

### Преимущества централизованной архитектуры

1. ✅ Простота управления - один сервер вместо 9
2. ✅ Легче обновлять - обновляете только центральный сервер
3. ✅ Меньше ресурсов - станции не тратят ресурсы на Node.js
4. ✅ Надежность - если сервер упал, просто перезапустите его
5. ✅ Единая точка управления - все команды идут через один сервер

## Настройка

### Шаг 1: Запуск центрального сервера

1. **Установите зависимости:**
   ```bash
   npm install
   ```

2. **Запустите сервер:**
   ```bash
   npm start
   # или
   node server.js
   ```

3. **Проверьте доступность:**
   - Сервер должен быть доступен по IP адресу (не только localhost)
   - Проверьте: `http://192.168.1.10:3000/station.html` (замените на IP вашего сервера)
   - В консоли должно быть: `✅ Локальные модули доступны`

### Шаг 2: Настройка станций

**Требования к станциям:**

1. **IP-адреса станций:**
   - Станции должны иметь IP-адреса в диапазоне `192.168.1.21` - `192.168.1.29`
   - Каждая станция автоматически получает номер от 1 до 9 на основе последнего октета IP:
     - `192.168.1.21` → Станция №1
     - `192.168.1.22` → Станция №2
     - ...
     - `192.168.1.29` → Станция №9

2. **Сеть:**
   - Все станции должны быть в одной локальной сети с центральным сервером
   - Центральный сервер должен быть доступен по IP-адресу (не только localhost)

**Что нужно сделать на станции:**

1. **Откройте браузер на станции**

2. **Откройте страницу с центрального сервера:**
   ```
   http://<IP_ЦЕНТРАЛЬНОГО_СЕРВЕРА>:3000/station.html
   ```
   Например: `http://192.168.1.10:3000/station.html`
   
   ⚠️ **ВАЖНО:** Используйте `station.html`, а НЕ `local-station.html`!

3. **Автоматическая регистрация:**
   - Страница автоматически определит IP-адрес станции
   - Автоматически определит номер станции (1-9)
   - Автоматически зарегистрируется на центральном сервере
   - Установит соединение через Socket.io

4. **Что происходит при открытии страницы:**
   ```
   📥 Страница загружается с центрального сервера
   🔍 Определение IP адреса станции
   📤 Отправка запроса регистрации на центральный сервер
   ✅ Регистрация успешна
   🔌 Подключение через Socket.io к центральному серверу
   📥 Получение подтверждения от сервера
   ✅ Станция готова к получению команд
   ```

5. **Если автоматическое определение не сработало:**
   - На странице появится форма для ручного ввода номера станции
   - Введите номер станции (1-9) и нажмите "Подключиться"
   - Или добавьте параметр в URL: `?station=1`

### Шаг 3: Настройка автозапуска браузера

На станции нужно настроить автоматический запуск браузера с нужной страницей.

📖 **Подробная инструкция:** [BROWSER_AUTOSTART.md](../deployment/BROWSER_AUTOSTART.md)

**Быстрый способ (Windows):**
1. Создайте ярлык браузера с параметрами:
   ```
   "C:\Program Files\Google\Chrome\Application\chrome.exe" --kiosk --app=http://192.168.1.10:3000/station.html
   ```
2. Скопируйте ярлык в папку автозагрузки (`Win+R` → `shell:startup`)

**Быстрый способ (Linux/Raspberry Pi):**
1. Создайте файл `~/.config/autostart/station.desktop`:
   ```ini
   [Desktop Entry]
   Type=Application
   Name=Station Browser
   Exec=chromium-browser --kiosk --app=http://192.168.1.10:3000/station.html
   ```

### Шаг 4: Проверка работы

**Проверка на станции:**
1. Откройте страницу станции: `http://<IP_СЕРВЕРА>:3000/station.html`
2. Должно отображаться "Станция X подключена"
3. Статус должен быть зеленым

**Проверка на центральном сервере:**
1. Откройте страницу управления: `http://<IP_СЕРВЕРА>:3000/local-host.html`
2. Должны отобразиться подключенные станции (зеленым цветом)
3. Видно IP-адрес и статус каждой станции

### Чеклист настройки

**На центральном сервере:**
- [ ] Установлен Node.js

- [ ] Запущен `server.js`
- [ ] Сервер доступен по IP адресу (не только localhost)

**На станциях:**

- [ ] НЕ запущен `server.js` на станции
- [ ] НЕ установлен Node.js на станции

## API управления

### Типы команд

Система поддерживает следующие типы команд:

- `navigate` - навигация между страницами
- `update-state` - обновление состояния станции
- `update-content` - обновление содержимого элементов страницы
- `execute-action` - выполнение действий
- `custom` - кастомные команды

### Socket.io события

#### Отправка команды станциям

```javascript
socket.emit('local-station-command', {
  stationNumbers: [1, 2, 3], // массив номеров станций или null для всех
  command: 'navigate',
  params: {
    page: 'quiz',
    roomCode: 'ABC123',
    quizId: 'gnu'
  }
});
```

#### Получение статуса от станции

```javascript
socket.on('local-station-status-updated', (data) => {
  console.log('Статус станции:', data);
  // data: { stationNumber, status, state, data, timestamp }
});
```

#### Получение состояния станции

```javascript
socket.emit('local-station-get-state', { stationNumber: 1 });
socket.on('local-station-state', (data) => {
  console.log('Состояние станции:', data);
});
```

#### Получение списка станций

```javascript
socket.on('local-stations-updated', (data) => {
  console.log('Список станций обновлен:', data.stations);
});
```

### HTTP API

#### Отправка команды через HTTP

```bash
POST /api/local/stations/command
Content-Type: application/json

{
  "stationNumbers": [1, 2, 3],
  "command": "navigate",
  "params": {
    "page": "quiz",
    "roomCode": "ABC123",
    "quizId": "gnu"
  }
}
```

#### Получение состояния станции

```bash
GET /api/local/stations/1/state
```

#### Получение статуса всех станций

```bash
GET /api/local/stations/status
```

#### Получение команд из очереди (HTTP polling)

```bash
GET /api/local/stations/1/commands
```

### Примеры использования команд

#### 1. Навигация - открыть квиз на станциях

```javascript
// Через Socket.io
socket.emit('local-station-command', {
  stationNumbers: [1, 2, 3],
  command: 'navigate',
  params: {
    page: 'quiz',
    roomCode: 'ABC123',
    quizId: 'gnu'
  }
});

// Через HTTP API
fetch('/api/local/stations/command', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    stationNumbers: [1, 2, 3],
    command: 'navigate',
    params: {
      page: 'quiz',
      roomCode: 'ABC123',
      quizId: 'gnu'
    }
  })
});
```

#### 2. Вернуться в режим ожидания

```javascript
socket.emit('local-station-command', {
  stationNumbers: [1, 2, 3],
  command: 'navigate',
  params: {
    page: 'waiting'
  }
});
```

#### 3. Обновление состояния станции

```javascript
socket.emit('local-station-command', {
  stationNumbers: [1],
  command: 'update-state',
  params: {
    statusText: 'Игра началась',
    showTimer: true,
    timerValue: 30
  }
});
```

#### 4. Обновление содержимого элементов

```javascript
socket.emit('local-station-command', {
  stationNumbers: [1],
  command: 'update-content',
  params: {
    selector: '#stationStatus',
    text: 'Новый статус',
    style: {
      color: '#00C159',
      fontSize: '24px'
    }
  }
});
```

#### 5. Выполнение действий

```javascript
socket.emit('local-station-command', {
  stationNumbers: [1, 2, 3],
  command: 'execute-action',
  params: {
    action: 'showQuestion',
    data: {
      questionNumber: 1,
      questionText: 'Вопрос?'
    }
  }
});
```

#### 6. Кастомная команда

```javascript
socket.emit('local-station-command', {
  stationNumbers: [1],
  command: 'custom',
  params: {
    type: 'myCustomAction',
    data: {
      customData: 'любые данные'
    }
  }
});

// На странице станции можно обработать через событие:
window.addEventListener('station-custom-command', (event) => {
  const { type, data } = event.detail;
  console.log('Кастомная команда:', type, data);
});
```

## Механизм доставки команд

### Надежная доставка команд

Система использует два механизма доставки команд для максимальной надежности:

### 1. Socket.io (приоритетный способ)

- Станция подключается к серверу через Socket.io при загрузке страницы
- Команды доставляются мгновенно в реальном времени
- Если соединение потеряно, автоматически переподключается
- Настройки переподключения:
  ```javascript
  {
    reconnection: true,
    reconnectionDelay: 1000,
    reconnectionDelayMax: 5000,
    reconnectionAttempts: Infinity,
    timeout: 20000
  }
  ```

### 2. HTTP Polling (резервный способ)

- Если Socket.io недоступен, станция опрашивает сервер каждые 2 секунды
- При потере соединения частота опроса увеличивается до 1 секунды
- Запрашивает команды через: `GET /api/local/stations/:stationNumber/commands`
- Команды хранятся в очереди на сервере до получения
- Автоматически активируется при потере Socket.io соединения

### 3. Очередь команд

**Как это работает:**

1. **Все команды добавляются в очередь на сервере:**
   - Команды сначала добавляются в очередь для каждой станции
   - Затем пытаются быть отправлены через Socket.io
   - Если Socket.io недоступен, команды остаются в очереди

2. **Получение команд:**
   - Через Socket.io: команды отправляются мгновенно при подключении
   - Через HTTP polling: станция получает все команды из очереди при запросе
   - При переподключении Socket.io все накопленные команды автоматически отправляются

3. **Преимущества:**
   - Команды не теряются даже при потере соединения
   - Гарантированная доставка через любой доступный канал
   - Автоматическое восстановление при переподключении

### Сценарии работы

#### Сценарий 1: Нормальная работа (Socket.io подключен)

1. Сервер отправляет команду → добавляет в очередь → отправляет через Socket.io
2. Станция получает команду через Socket.io
3. HTTP polling работает в фоне (низкая частота), но не используется активно

#### Сценарий 2: Потеря Socket.io соединения

1. Сервер отправляет команду → добавляет в очередь → Socket.io недоступен
2. Команда остается в очереди
3. Станция обнаруживает потерю соединения
4. HTTP polling увеличивает частоту до 1 секунды
5. Станция получает команду через HTTP polling
6. Socket.io пытается переподключиться в фоне

#### Сценарий 3: Переподключение после потери соединения

1. Socket.io успешно переподключается
2. Сервер отправляет все накопленные команды из очереди через Socket.io
3. HTTP polling возвращается к нормальной частоте (2 секунды)
4. Станция синхронизирует состояние с сервером

## Устранение проблем

### Проблема: Страница не загружается

**Симптомы:** Страница не открывается или показывает ошибку подключения

**Решение:**
1. Проверьте доступность сервера: `ping 192.168.1.10` (замените на IP сервера)
2. Проверьте, что сервер запущен: `curl http://192.168.1.10:3000/station.html`
3. Убедитесь, что URL правильный в настройках автозапуска браузера
4. Проверьте настройки файрвола на сервере (порт 3000 должен быть доступен)
5. Проверьте, что станция и сервер в одной сети

### Проблема: Станция не подключается к серверу

**Симптомы:** Станция не отображается как подключенная на странице хоста

**Решение:**
1. Проверьте, что центральный сервер запущен
2. Проверьте, что станция и сервер в одной сети
3. Проверьте консоль браузера (F12) на ошибки
4. Проверьте, что открываете страницу с правильного IP адреса центрального сервера
5. Проверьте, что IP-адрес станции в диапазоне 192.168.1.21-29

### Проблема: Станция не определяется автоматически

**Симптомы:** Станция не может определить свой номер

**Решение:**
1. Убедитесь, что IP адрес станции в диапазоне 192.168.1.21-29
2. Проверьте, что сервер доступен по IP (не только localhost)
3. Используйте параметр URL: `http://192.168.1.10:3000/station.html?station=1`
4. Введите номер станции вручную на странице

### Проблема: Команды не доходят

**Симптомы:** Команды отправляются, но станции их не получают

**Решение:**
1. Проверьте консоль сервера на наличие ошибок
2. Проверьте, что станция подключена (зеленая на странице хоста)
3. Проверьте консоль браузера на станции (F12)
4. Проверьте логи на сервере (должны быть эмодзи: 📤, ✅, ⚠️, ❌)

### Проблема: Socket.io не работает

**Симптомы:** Станция не может подключиться через Socket.io

**Решение:**
1. Система автоматически переключится на HTTP polling
2. Команды все равно будут доставлены, но с задержкой до 2 секунд
3. Проверьте настройки файрвола (порт 3000 должен быть открыт)
4. Проверьте консоль браузера на ошибки WebSocket

### Проблема: Браузер не запускается автоматически

**Симптомы:** После перезагрузки браузер не открывается

**Решение:**
1. Проверьте настройки автозапуска (см. [BROWSER_AUTOSTART.md](../deployment/BROWSER_AUTOSTART.md))
2. Убедитесь, что путь к браузеру правильный
3. Проверьте права доступа к файлам автозагрузки
4. Проверьте логи системы (Linux: `journalctl -u station-browser`)

### Проблема: Конфигурация джойстика не сохраняется

**Симптомы:** Настройки джойстика не сохраняются между сессиями

**Решение:**
1. Убедитесь, что станция правильно определена (проверьте номер станции)
2. Проверьте подключение к серверу (Socket.io должен быть подключен)
3. Проверьте логи сервера на наличие ошибок сохранения конфигурации
4. Проверьте права на запись в папку `data/` на центральном сервере

## Резюме

**Что нужно включить на станциях:**
1. Открыть страницу `/station.html` в браузере
2. Дождаться автоматической регистрации и подключения

**Как управлять станциями:**
1. Через интерфейс хоста (`/local-host.html`) - самый простой способ
2. Через Socket.io события `local-station-command`
3. Через HTTP API `/api/local/stations/command`

**Что происходит автоматически:**
- Определение IP и номера станции
- Регистрация на сервере
- Подключение через Socket.io
- Получение команд в реальном времени
- Переключение на HTTP polling при потере соединения
- Получение накопленных команд при переподключении
- Очередь команд гарантирует доставку даже при временных сбоях
