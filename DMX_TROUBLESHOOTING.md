# Устранение проблем с DMX освещением

## Проблема: ESP32 не работает из веб-интерфейса

Если ESP32 доступен напрямую (можно зайти на его IP и управлять каналами), но не работает через сервер, проверьте следующее:

### 1. Проверка подключения к ESP32

#### На Windows:
mDNS (.local домены) может не работать из коробки. Используйте IP адрес напрямую:

1. Узнайте IP адрес ESP32:
   - Зайдите на веб-интерфейс ESP32 напрямую (обычно показывается на главной странице)
   - Или проверьте в настройках роутера

2. Измените конфигурацию в `server/dmx/dmx-config.json`:
```json
{
  "interface": {
    "type": "esp32",
    "host": "192.168.1.100",  // ← Укажите IP адрес ESP32 вместо "esp32-dmx.local"
    "port": 80
  }
}
```

3. Перезапустите сервер

#### На Linux/Mac:
mDNS должен работать. Если не работает, также используйте IP адрес.

### 2. Проверка логов сервера

При отправке запросов через веб-интерфейс проверьте логи сервера. Должны быть сообщения:

```
🔗 Отправка на ESP32: http://...
📦 Данные для ESP32: ...
📥 ESP32 ответил: ...
```

Если видите ошибки типа:
- `ENOTFOUND` - не удается разрешить имя хоста
- `ECONNREFUSED` - соединение отклонено
- `ETIMEDOUT` - таймаут соединения

→ Используйте IP адрес вместо .local домена

### 3. Проверка доступности ESP32

Проверьте, что ESP32 доступен с сервера:

```bash
# На сервере выполните:
curl http://192.168.1.100/api/dmx/status
# или
curl http://esp32-dmx.local/api/dmx/status
```

Если команда не работает, ESP32 недоступен с сервера (проблема сети).

### 4. Проверка формата данных

ESP32 ожидает следующий формат:

```json
{
  "channels": {
    "1": 255,
    "2": 128,
    "3": 0
  },
  "startAddress": 1
}
```

Где:
- `channels` - объект с относительными номерами каналов (1-9 для LM70S)
- `startAddress` - начальный DMX адрес

### 5. Проверка консоли браузера

Откройте консоль браузера (F12) и проверьте ошибки при отправке запросов.

### 6. Проверка статуса DMX контроллера

Откройте в браузере: `http://localhost:3000/api/dmx/status`

Должен вернуться JSON с информацией о контроллере. Если `available: false`, проверьте логи сервера при запуске.

## Частые проблемы и решения

### Проблема: "ESP32 недоступен"
**Решение:** Используйте IP адрес вместо .local домена в конфигурации

### Проблема: "Запрос отправлен, но ответа нет"
**Решение:** 
1. Проверьте, что ESP32 подключен к WiFi
2. Проверьте, что сервер и ESP32 в одной сети
3. Проверьте файрвол на сервере

### Проблема: "ESP32 вернул ошибку"
**Решение:** Проверьте логи ESP32 (Serial Monitor в Arduino IDE) для деталей

### Проблема: Каналы не обновляются
**Решение:**
1. Проверьте логи сервера - должны быть сообщения об отправке на ESP32
2. Проверьте, что формат данных правильный (относительные каналы 1-9)
3. Проверьте, что startAddress правильный

## Отладка

Включите подробное логирование в коде. Все запросы к ESP32 логируются в консоль сервера с префиксами:
- `🔗` - отправка запроса
- `📦` - данные запроса
- `📥` - ответ от ESP32
- `❌` - ошибка
