3) Единый протокол Socket.IO (обязательный стандарт)
Новый протокол (единый для всех игр):
- room:join
- room:leave
- room:state (сервер -> всем клиентам, единый формат)
- game:action (клиент -> сервер, действия внутри конкретной игры)
- system:error (опционально)

Принцип
- UI не "думает", он только:
  - подключается
  - join
  - слушает room:state
  - отправляет game:action
- Вся логика - на сервере.

Примеры
- Player answer (quiz):
  game:action { roomCode, type: "answer", payload: { answerIndex: 2 } }
- CHGK submit:
  game:action { roomCode, type: "submit", payload: { text: "..." } }
- Host start:
  game:action { roomCode, type: "start" }

4) Единый объект состояния комнаты (room:state)
Сервер должен отправлять клиентам единый JSON состояния.

Рекомендуемая структура (минимум):
{
  roomCode: string,
  gameId: "quiz" | "chgk" | "solo" | ...,
  phase: string,
  phaseEndsAt: number | null,      // Unix ms, если есть таймер
  players: [
    { id, name, score, isReady, isConnected, stationId? }
  ],
  host: { id, isConnected },
  ui: {                           // то, что UI должен отображать
    title?: string,
    question?: { text, options?, media? },
    results?: { correct?, perPlayer? },
    board?: any,                  // для "Своя игра"
  },
  meta: { createdAt, updatedAt }
}

Важно
- phaseEndsAt считается на сервере, клиент лишь рисует отсчет.
- Права/видимость: getState(room, role) может фильтровать поле ui.

5) Единая архитектура серверной логики игр (реестр движков)
Создать папку:
- server/games/

Файлы:
- server/games/index.js (реестр)
- server/games/quiz.game.js
- server/games/chgk.game.js
- server/games/solo.game.js (если соло оставляем как отдельную игру)
- (позже) server/games/guess.game.js, server/games/jeopardy.game.js

Единый интерфейс для всех игр (обязателен):
- createRoom(params) -> room
- join(room, client) -> void
- handleAction(room, client, action) -> void
- getState(room, role) -> state
- tick(room) -> void (если есть таймеры)

Роутер на сокетах (в server.js или server/core/socket-router.js)
- при room:join:
  - найти/создать room
  - определить role
  - games[room.gameId].join(...)
  - emit room:state
- при game:action:
  - найти room
  - games[room.gameId].handleAction(...)
  - emit room:state

7) Локальные станции: перестать быть отдельным режимом
Ключевая мысль:
- station - это тот же player client, только:
  - имеет stationId
  - может читать input с джойстика
  - может получать admin-команды навигации/диагностики

Что сделать:
- Убрать отдельный протокол local-* для геймплея.
- Station подключается так:

- Нажатия на джойстике превращаются в game:action, как у обычного игрока.
- Управление станциями (deploy/status/ping/joystick-check) оставить как admin REST:

12) Чеклист приемки (Definition of Done)
- Любая игра использует room:join + game:action + room:state.
- CHGK больше не использует global.intellectualRooms, а работает через rooms Map.
- Локальные станции играют через тот же протокол, что и обычные игроки.
- Серверные таймеры везде: phaseEndsAt на сервере.

- DMX получает события через event bus (не напрямую из UI).
- Старые URL не ломают пользователей (редиректы работают).
